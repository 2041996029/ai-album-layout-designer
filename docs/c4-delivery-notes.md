# C4 交付说明与实现取舍

C4 将配置发布、持久任务、云端规则排版与导出、订单、会员点数、兑换、退款和财务对账接入同一服务端事实源。网页新增会员、订单与兑换、任务中心；财务后台有独立构建入口。

这份记录供审阅实现与后续接入使用，不表示生产服务已经部署。真实短信、微信支付／虚拟支付、存储、密钥服务、渠道账单和生成式 AI 没有凭据时保持未配置。本地签名渠道与验证码传输仅用于受控测试，不代表真实渠道准入。

## 接入与验收

- 迁移入口为 `scripts/migrate-c3.ts`，依次应用初始合同、C3 运行表及 `002_order_snapshots`、`003_redemption_batch_policy`、`004_financial_adjustments`；各增量迁移有对应回退文件。不得以删除订单或账本代替回退。
- `createRuntime` 的可信部署选项绑定渠道、身份验证、密钥、存储与只读账单适配器。配置载荷本身不会自动取得外部访问资格。
- `C4_REDIS_URL` 启动实际队列与恢复循环。导出还需要可信渲染器身份、存储和预检签名配置；兑换需要服务端 pepper 与限速服务。缺失条件会明确拒绝相应操作。
- 身份验证由页面引导输入验证码，系统内部取得用途与会话绑定的一次性证明；不要求使用者复制协议凭证。未配置身份渠道时会显示不可用。
- 完整检查包括 `npm run typecheck`、`npm run api:types:check`、网页及后台构建、带临时 PostgreSQL／Redis 的完整单测、全部浏览器测试。最终结果以本分支 PR 的验证记录为准。

## 实现取舍（Rulings I made）

以下按执行台账中的决定顺序保留；重复条目是后续明确或修正，不代表额外产品功能。每项同时说明判断错误时的返工范围。

1. 技能辅助脚本不可读取时，在忽略目录内生成等价的任务简报、台账及审查包。若有误，只需调整记录格式，需求不变。
2. 使用独立 C4 工作树和分支，保留原预览分支。若有误，可撤回工作树或分支，不影响原项目。
3. 计划中的函数签名以依赖注入的服务方法实现，仍导出约定类型。若有误，需要调整内部适配器，不改变公开协议。
4. 每个工作树独立执行 `npm ci`，避免共享依赖造成模块身份和可信对象校验失效。若有误，仅需修正安装环境。
5. C4 不只新增服务，还接通已有 C4、配置、密钥及能力接口与页面入口。若有误，返工范围是集成及其测试，不会自动连接生产渠道。
6. 配置合同实际有 21 类，以生成的 schema 为准，覆盖独立的 `albumDefaults`。若有误，需要修正合同覆盖，而非另建配置模型。
7. 建任务时显式传入可信创建者和已冻结快照，不推断工作区所有者；快照、锁定、任务及 outbox 同事务。若有误，只调整内部调用，不改公开 DTO。
8. 人工权益调整是已计划功能，但原合同缺接口；补严格的管理接口、生成类型和反例，要求财务角色、理由、工单、幂等及前后审计。若有误，需要修订这部分新增合同。
9. 旧幂等工具不支持任务要求的真实工作区键，且 SQL 禁止回填身份字段；因此使用同一表上的事务内锁及查询／插入。若有误，返工是少量幂等封装，不削弱数据库隔离。
10. Job kind 使用 SQL／生成合同的完整 10 类，包含 `asset_analysis` 和 `deletion`，修正计划中较窄的示意联合。若有误，需修订类型与合同的一致性。
11. 公开导出 DTO 使用预检令牌与规范化哈希；保留计划的内部导出方法，通过单一门面映射。浏览器预检辅助入口归 worker 所有，复用 C1。若有误，只需调整内部门面或辅助构建。
12. CI 安装固定 Playwright Chromium；显式浏览器路径存在时才采用。JPEG 质量必须真正影响产物，不假称已应用配置。若有误，需要调整 CI 或编码适配，不改 C1 文档模型。
13. 未知支付查询返回空结果，不伪造关闭状态。购买快照使用持久的 `002` 业务表，不借用可清理的七天幂等记录。若有误，返工涉及窄范围快照迁移与适配，而不是丢失财务依据。
14. schema 无单独档位键，因此以规范化权益特征定义同档，排除商品 ID、价格、期限和赠点；月付年付可累计。退款冻结由在途状态和来源事实推导。若有误，需要修订档位映射与批次投影，并核对历史权益。
15. 跨档购买在准入处阻止；已经并发收款的冲突不回滚支付事实，而转人工复核且不发冲突权益。若有误，代价是额外人工处理，不是静默换算或丢失收款。
16. `003` 持久保存兑换批次规则和版本。创建响应仅首次返回原码；重放只返回元数据，不制造输出对象 ID 或持久原码。丢失首次响应后原码不可恢复，可由授权管理员停用并重发。若有误，需要修订窄范围接口和批次规则，不暴露原码。
17. 停用兑换批次接口增加必填理由参数，保留版本、幂等与重新认证。若有误，需要修订新增参数及调用方；不记录完整查询值。
18. 退款有独立的可信回执注册表与原退款查询适配器，不把普通支付对象当退款证明。累计退款由成功记录推导，保留原支付金额；沿用同一撤销流水。若有误，需要调整内部渠道适配，不自动执行真实退款。
19. 会员投影排除冻结来源；导出接受事务内再次锁定并复核权益，关闭读权益后被退款的竞态。已接受任务仍用冻结快照。若有误，只需修订事务守卫及并发测试。
20. 无全面使用流水时，已生效会员的退款进入人工复核；自动处理仅限规则允许且未生效、未消耗的续期。强制成功回执仍保留财务事实。若有误，代价是偏保守的人工复核，不虚称未使用。
21. `004` 增加明确的人工调整来源，关联不可变调整事实，不伪装订单或兑换。对账使用持久、确定标识的审计事实，重复运行不补发。若有误，需修订新增来源迁移与对账投影。
22. 同步完成的配置测试可没有 jobId；排队／运行测试必须关联实际任务。若有误，需要恢复异步任务约束或修订相应消费方，不生成假任务。
23. 架构决策完成后，剩余集成与测试交给标准模型执行，不重新设计；全分支审查仍采用最强可用模型。若有误，代价是实现复核或返工，不改变产品合同。
24. 已使用会员收到强制退款回执后仍保留财务复核，对账不把金额相等误当权益已经正确反转。若有误，代价是多一次复核，不重复发放。
25. 明确 `PaymentLaunch` 的 `qr`／`mini_jsapi`／`mini_virtual` discriminator 映射，保持线上的字面值。若有误，只需修正生成类型映射。
26. 重试建立有父任务记录的新任务，重新检查权限、预检与权益；仅相同资源、设置及警告可沿用确认。AI 任务缺新报价时明确要求重新报价。若有误，需要调整重试适配和审计，不重提未知付费请求。
27. 列表超过 100 条而声称无更多是合同缺陷，不能留待后续；先补分页再交付。若有误，代价是分页实现与测试返工，不隐藏业务记录。
28. 分页复用签名游标，绑定操作、主体／工作区与筛选，按 PostgreSQL 时间和 ID 稳定取 `limit+1`；页面提供加载更多。若有误，旧游标可能失效并需重新加载，但不静默截断。
29. 人类验证复用现有 challenge、关联身份检查及五分钟一次性证明，绑定当前会话与用途。可信短信传输由部署提供；默认不可用，页面不要求粘贴协议 token。若有误，需要调整挑战适配与角色校验，不绕过身份验证。

## 尚需外部接入的边界

真实商户准入、供应商凭据、渠道规定的 ACK、存储／密钥服务、短信与账单传输及生产部署需要独立接入验收。生成式 AI 模型调用与新报价属于 C5。首次兑换码响应丢失后不能恢复原码；已生效会员缺全面未使用证明时走人工复核。这些限制不会由本地模拟测试自动解除。
