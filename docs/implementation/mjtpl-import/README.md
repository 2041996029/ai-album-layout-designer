# MJTPL 导入与 96 个原创版式

## 使用方法

- 原创模板：打开「模板与滤镜」→「模板」→ 系列选择「主题套装 · 96 跨页」，再选分类。
  12 个风格分别有 8 个跨页：开篇、两个双图、两个三图、两个四图、收尾；照片、文字和装饰保持独立可编辑。
  选择其中任一版式后，可点击「使用整套主题（8 跨页）」进入整套选页/选片界面。
  原有 5 个模板和 36 个基础版式及其签名保留，总计 137 个内置跨页。
- 导入模板：「模板与滤镜」→「我的模板」→「导入 .mjtpl」。导入后先查看源预览和转换图层预览、兼容性报告。
- 单页应用：为每个照片槽选择用户照片，再点击「替换当前跨页」，可以一次撤销。
- 整本应用：勾选跨页，展开「使用此主题排整本」，选入对应数量的照片，确认应用。按照勾选顺序成册，不会静默用通用网格替代源版式。
- 若主题比例不同，可点击「新建匹配尺寸作品」，当前作品会保存保留，照片素材沿用。
- 不支持排版的文字优先以对应文字栅格保留外观；选择该图层后可显式「转为可编辑文字」，使用本地字体重新排版，允许撤销。
- 定期从顶部备份项目 ZIP。已应用的图层、蒙版、字体和素材随项目备份恢复，不依赖模板库继续存在。

## 当前兼容范围

MJTPL ZIP 的 formatVersion=1、scene schemaVersion=3。按包清单校验素材、页面与预览 SHA-256。
标准 cm/px 尺寸、归一化坐标、ARGB 颜色、旋转、独立 PNG 装饰、照片槽 alpha 蒙版、可准确映射的裁剪受支持。
实际嵌入且字形/排版可容纳的400/700字重可编辑；缺失字体或排版无法重现时保留独立文字图像，明确给出提示。
未知节点、复杂混合/变换、缺失必要素材、不支持的文字且无对应栅格会阻止应用该页。
JPEG EXIF 素材目前会明确报告不支持，不宣称已完成方向归一化。已检查的实际样本素材均为 PNG。
源包预览可能带“拖入照片完成替换”的编辑器提示；转换画布显示包内真实照片槽像素，不复制该提示。

| 天赐良缘 | 15 | 45 | 第4、第14页各有一处无可用字体且无对应栅格的文字，阻止应用这两页 |
| 纯爱永恒 | 15 | 55 | 部分文字保留外观 |

每个主题至少一页通过源预览/共享渲染对照，修复了嵌入字体出现额外换行的问题。
这不是对全部105页逐像素等价的声明。私有样本与对照截图不提交公共仓库。
另5个不同名称的上传包超过执行器附件读取的32MiB上限，仍未验证；浏览器产品没有32MiB限制。

## 产品限制与资源生命周期

压缩包≤256MiB、解压总量≤512MiB、单条目≤64MiB、≤10000条目、≤50跨页、每页≤100递归图层。
图像≤80MP、字体≤20；项目最多500张用户照片、2000个模板装饰/蒙版/文字栅格资源。
私有主题单独存储在浏览器 IndexedDB，按源包内容哈希去重，同名不同内容保留不同版本。
导入取消或失败不会产生半个可选主题，也不会改变作品。移除主题库中的包不会删除已经复制到作品的资源。
原样片和装饰不计入用户照片选片；已绑定照片沿用C2完整性校验、锁定保护和过期方案阻止。
源版式允许出血区装饰，但只有严格匹配已验证源几何的导入候选可使用源超出页面部分；普通新排版不能绕过边界检查。

## 开发复现

- `npm test`
- `npm run build`
- `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`
- `npx tsx packages/template-import/verify-samples.ts --dir /path/to/private/samples`
- `npx tsx scripts/build-theme-templates.ts`
- `npx tsx scripts/preview-theme-templates.ts`

不调用外部 AI。发布产物仅含程序和原创版式，不包含用户上传的包、人物样片和专用字体。
