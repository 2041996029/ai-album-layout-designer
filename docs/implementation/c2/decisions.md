# C2 实施裁决与影响

| 裁决 | 原因 | 限制／若判断错误的代价 |
|---|---|---|
| 沿用现有 Editor/App，替代计划中的不存在的 EditorPage | 避免第二套编辑器状态 | 后续重构时需迁移向导入口 |
| 本地包不引入 PostgreSQL/Redis | 本阶段无服务器事务 | 不构成云端并发或事务验证 |
| 同成本分配稳定取首个连续分段，不用种子扰动分配 | 保留明确照片顺序 | 种子不保证产生不同分配；差异来自真实几何变体 |
| 槽位数不匹配时采用原创版本化网格，以模板作为风格来源 | 固定模板不能偷偷丢片或重复填槽 | 网格不保证与源模板逐框一致，视觉质量仍需盲评 |
| 本地候选绑定冻结输入与当前会话的验证来源 | 防止使用伪造或过期候选 | 导入的候选 JSON 不能直接应用，必须重新验证生成 |
| 应用同时绑定完整草稿、revision，UI 额外监测保存版本 | C1 自动保存版本与历史草稿版本分开管理 | 保存变化会使旧方案失效，需要重新生成；不是云端 CAS |
| 项目恢复保留 layoutSourceProjectId，不重写原始输入哈希 | 保留可核查来源且支持反复恢复 | 来源字段不是账号权限凭证，云端仍需逐资源鉴权 |
| apply-layout 命令绑定已验证对象与精确载荷 | 防止验证后篡改及直接反序列化绕过 | 服务端或未来跨线程调用需经验证工厂重建命令 |
| 使用旋转与祖先缩放后的世界坐标检查所有角点 | 与共享渲染器保持一致，避免锁定层间接越界 | 已锁定的越界内容会阻止生成，需要用户修复或解锁 |

独立评审的五项 Important 均有失败反例，再实现修复；没有遗留 Minor。普通层级调整不改变照片映射集合；照片删除、替换、未授权重复或移至其他跨页仍需重新核对完整性。
