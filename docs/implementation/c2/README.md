# C2 本地整本排版实现

基于 C1，新增 `@album/layout` 与网页「智能排版」向导。此目录记录实际实现，不等同于已部署或商业视觉验收通过。

## 用户流程

导入照片 → 智能排版 → 选择场景、跨页数量与每页容量 → 调整选片和顺序 → 生成方案 → 预览真实照片 → 应用。应用后所有内容仍是可编辑图层，一次撤销恢复整本。打开向导前先保存；保存冲突必须先解决。

默认全选照片都使用，禁止重复。允许留下照片或重复必须显式设置；候选显示未使用照片与重复位置。局部重排范围外跨页不变，锁定图层及其祖先分支保留。容量不足给出最少跨页数，不静默删片。真实有效候选最多三个，不保证每次三个。

普通排版在浏览器 Worker 中计算，不上传照片、不调用外部 AI、不扣 AI 点数。拍摄时间目前未在导入端保留，因此选择时间排序仍按用户顺序回退；没有主体提示时明确标记未知，不宣称识别人脸或保护主体。

## 代码入口

- `packages/layout/src/prepare.ts`：正式 v1 JSON Schema 校验、稳定排序、冻结输入/策略与 SHA-256。
- `allocate.ts`：有界连续分段动态规划，选片/重复许可、容量、局部范围与锁定约束。
- `compose.ts` / `score.ts`：固定页框、cover/contain 裁剪、主体提示风险与五项评分。
- `integrity.ts` / `candidates.ts`：从真实照片用途层重建清单，复核锁定与硬约束，按几何去重。
- `apply.ts`：候选来源与完整草稿校验、一次文档命令、导出清单校验。
- `apps/web/src/layout/`：Worker、可取消控制器、向导、共享渲染器预览。
- `packages/document/src/commands.ts`：`apply-layout` 原子命令；`packages/export/src/preflight.ts`：实际清单与输入策略哈希预检。

## 实施裁决

1. C1 模板是固定槽位。照片数恰好匹配且宽高比一致时使用原注册模板；其他情况使用 `local-grid-v1` 原创页框，模板仅提供风格来源。原模板不变，不填入重复占位照片。图层带几何版本，模板引用仍记录源模板。
2. C1 历史草稿 revision 与自动保存提交 revision 分开管理。应用同时绑定完整草稿、输入和候选来源，界面额外监测保存 revision；旧候选不会覆盖新编辑。
3. 带锁定子层的祖先分支整体保留，防止通过移动祖先间接移动锁定内容。局部范围外整页保持原样。
4. CPU 本地包不引入 PostgreSQL/Redis。服务器权限、云端 CAS、微信和付费 AI 是后续模块。
5. 同成本分配保持稳定首选分段；种子绑定输入，候选通过固定几何变体区分，不打乱用户顺序。

## 验证

开发期间已执行输入、容量、构图、清单、应用/撤销和导出集成测试。最终结果见 `acceptance-results.json`。浏览器测试含真实 12 张照片导入、四跨页预览/应用/撤销、容量冲突、旧候选禁用和取消计算。

本地命令：

```bash
npm ci --ignore-scripts
npm run typecheck
npm run test:unit
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

`CHROMIUM_PATH` 只在已安装系统 Chromium 时设置；CI 使用 Playwright 安装的浏览器。

## 尚未宣称完成的验收

视觉盲评 ≥80% 是后续目标。颜色评分无授权摘要时使用中性分值；未接主体识别服务。50/200 张浏览器观察使用小尺寸合成测试图，不能外推为 80MP 大图、移动端或 500 张极限性能承诺。专业印刷、云端排版任务及小程序尚未在本阶段实现。

## 独立评审修复

评审识别的五项重要问题均补反例后修复：项目包导入保留原排版项目来源；照片清单按稳定映射集合比较，正常层级调整不误拦；先满足锁定的重复次数再填最低容量；使用与渲染器一致的旋转/祖先缩放矩阵验证世界坐标；应用命令绑定已验证对象及其精确载荷，克隆或修改的命令不能执行。

`layoutSourceProjectId` 记录恢复项目时的原排版来源，不是服务器权限凭证。文档身份与数据权限仍需后续云端模块校验。`apply-layout` 是当前会话内部命令，不能直接反序列化未信任 JSON 执行；后续服务端应先验证候选再经工厂创建命令。
