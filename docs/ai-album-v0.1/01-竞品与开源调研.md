## 3. 三种实施路线

| 路线 | 优势 | 成本与约束 | 适用判断 |
|---|---|---|---|
| A：Fabric.js＋自有相册模型（推荐） | 核心编辑体验可控、可测试、可逐步适配小程序与 App | 前期编辑器工作量最大，需解决渲染和历史记录 | 持续经营产品、专业多页与消费者轻编辑共存 |
| B：快图开源版二开 | 现成交互多，可更快验证网页编辑体验 | 需先审计依赖、版本和产品耦合；无法据 README 承诺节省百分比 | Vue 团队、接受继承其架构且审计通过 |
| C：商业编辑器 SDK | 减少工具栏、文字编辑和基础导出研发 | 持续授权费、许可边界、服务依赖；小程序仍单独实现 | 交期紧、预算能覆盖合同与持续费用 |

推荐 A 的依据是本产品的长期价值集中在相册文档、AI 布局与跨端共享。若团队已掌握 Vue 且想优先验证市场，B 值得做短期技术验证；C 必须拿到具体报价后才可比较总拥有成本。此处没有替用户做最终采购决定。

## 4. 建议先验证的技术风险

1. 同一文档包含中文混排、半透明图层、裁剪、33 种滤镜时，网页与导出的差异。
2. 50 个内页跨页、500 张原片的缩略图加载、分页渲染与内存占用。
3. 小程序只修改可编辑字段后，网页的高级图层是否完整保留。
4. 国内 AI API 的水墨、淡彩、人像保留效果与单次可用结果成本。
5. 小程序虚拟权益支付、账号绑定与手机端付费准入的实际可用路径。

## 5. 大陆上线资料与核验边界

网信办《人工智能生成合成内容标识办法》已于 2025-09-01 施行，涉及显式、隐式标识和下载导出等场景。本产品应将生成标识作为素材与导出数据链的一部分。是否适用具体条款及备案／评估流程，需要结合实际服务方式确认；文档中的实现策略不是法律意见。[官方正文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。

微信开发文档部分页面本次无法直接打开。腾讯云 CloudBase 官方组织仓库中的[虚拟支付参考](https://github.com/TencentCloudBase/skills/blob/main/skills/cloudbase-wechat-integration/references/virtual-payment.md)明确区分虚拟支付与普通微信支付。它是辅助资料，不能代替主体后台的当前准入规则、合同和官方 API 文档。费用、iOS 支持、最低客户端版本不写死在本产品承诺中。

微信支付普通商户流程的签名验证、重复通知与查单，可参考[支付回调和查单指引](https://pay.wechatpay.cn/doc/v3/partner/4012082568)及[通用参数与 UnionID 说明](https://pay.wechatpay.cn/doc/v3/merchant/4012068676)。虚拟支付采用独立适配器，不能照搬同一组回调与签名代码。
