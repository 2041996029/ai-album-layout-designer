## 执行约定

推荐本会话按依赖顺序实施，单元完成后独立复核；如用户选择逐任务多AI实施复核，则按对应流程处理。当前全程AI偏好已确认，具体代码执行方式和最终基线评审在启动编码时落实；不再询问人工团队人数。

每项先确认有效失败，再实现该功能，跑针对性验证并提交；证据写docs/implementation/<unit>，服务模式区分mock/sandbox/live。必要的真实服务账号在接入时集中确认。技术选择造成接口变化时同步修改OpenAPI/schema/SQL/计划/页面/用例。

## 本轮统一修订

- API/SQL任务采用八个状态，确认上游用running＋providerSubmissionState=unknown；不另存unknown_upstream。
- 订单收款与履约分维度，refund使用明确查询状态；支付渠道统一wechat_pay/wechat_virtual。
- 图像wire format为jpeg，文件扩展名可.jpg；ZIP仅为多面／隐私打包产物，非单面格式。
- API模板场景包含ink；模板槽位、占位资源与实例绑定显式定义，草稿种子不是可直接发布的请求。
- 工作区采购／兑换／退款首期仅owner，admin管理设置／作品素材；页面中的workspace_admin是该工作区admin的界面名称，不能当平台管理角色。
- API采用NestJS＋FastifyAdapter，不在不同单元混用两套服务端框架；精确依赖和兼容性在首项技术验证锁定。
- 外部textSuggestion为可选预留关闭，图像GenerationInput不能当文本计费接口；手工标题编辑与规则排版独立可用。
