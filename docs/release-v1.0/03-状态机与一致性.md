# 状态机、事务与一致性合同

## 1. 任务

queued→running→packaging（导出）→succeeded；可重试错误running→retry_wait→queued；终态failed／cancelled。cancel_requested为请求状态，worker在安全边界终结；succeeded若先赢返回已有结果。claim递增fence并设置lease_until；heartbeat和结果提交必须匹配当前fence且租约未失效；旧worker只允许清理自己的临时对象。

jobs.state不含unknown_upstream；生成确认中表示running＋providerSubmissionState=unknown、stage=confirming_upstream。平台配置测试／对账／恢复演练使用服务端创建的platform工作区，公开创建工作区仅允许personal／studio。

每次任务提交有workspace＋Idempotency-Key唯一，保留7天；同key不同payload409。任务＋业务快照＋资源pin＋必要预占＋outbox同事务。投递器至少一次，消费者以jobId和数据库状态去重；不能宣称消息恰好一次。终态与有效产物唯一条件提交后才允许下载。

建议重试最多3次，退避10／30／90秒加抖动。坏schema、缺资源／权限、缺字体、文本溢出、内容拒绝不重试；OOM不能用相同资源盲试。排队公平性按工作区，免费任务有最大等待保护。重试终态失败任务为新jobId，关联parentJobId并重新验证权限／配额。

## 2. 文档与候选

文档CAS更新：锁项目→确认expectedRevision→校验字段／资源所属／授权／预算→追加revision和hash→更新current指针。冲突返回409和可恢复草稿；不自动合并；未知同版本字段保存原样。模板／滤镜发布不能改变旧revision。

候选生成不更新作品：固定输入、模板／算法版本和seed；可行性硬约束先行，再评分。应用时验证baseRevision、inputHash和manifest；从候选真实图片角色重新派生照片分配，对比锁定项和未选跨页→单次事务写revision。all＋forbid时任一遗漏／重复都阻断，与视觉得分无关。

## 3. 支付、退款与权益

v1规范将订单收款状态与履约状态分开：orders.state为pending／paid／closed／refund_pending／partially_refunded／refunded；fulfillmentState为unfulfilled／fulfilled／reversed／manual_review。创建后pending；已收款待履约为paid＋unfulfilled，完成为paid＋fulfilled；历史v0.1的created／fulfilling／fulfilled是过程说明，不再作为独立orders.state写入。付款事实不因退款抹掉。回调原始body验签，验证商户／应用／订单／金额／商品／币种，唯一payment_event；查单和回调共享履约事务。front-end success只触发查单。渠道需同步履约ACK时按其官方合同执行。

退款记录state为requested→submitted／unknown→succeeded／failed／manual_review；其中unknown只查询原退款操作。用户展示的“退款处理中／已退款”等是这些状态的映射，不与订单收款状态混用。先冻结可退款grant／lot，查询已有任务，再调用幂等退款adapter；未知退款状态查询不重复发钱。确认退款后一次撤销对应权益，其他订单权益保留。已消耗部分按公开政策人工处理或记录损失，不把余额改负数。正常退款不强制需要未配置的第二个人；异常人工财务覆盖可选配置更严格复核。

grant按来源订单＋grant_type唯一；同档续购start=max(now,current_end)，end=start+duration_days，初期不隐式跨档折算，不自动续费。权限实时由grants计算，定时任务仅通知／缓存。已接受任务使用entitlementSnapshot，排队期间到期不取消。

## 4. 点数与平台预算

available=未过期lot余额－有效reservation；lot按最近到期优先，金额与点数整数。接受quote时同事务锁定用户可用lot和稳定accountBillingId预算账户，检查并发、报价版本／有效期，建立reservation和job／outbox；缺一回滚全部。

结算operationId唯一且reservation状态条件变更，成功一次settle；失败一次release到原lot，赠送点数到期不因失败重置有效期。供应商状态未知保持预占并查询，建议30分钟终局后释放；迟到结果不重新发布／补扣，可能供应商迟到成本归平台并对账。

平台预算按采购账户／环境／北京时间日归属，同账户跨连接和模型共享；版本变更和午夜都不清掉未终局预占。停接新任务保留查询／结算；每日对账区分估计费用、实际费用和用户点数。

## 5. 存储、目录与删除

上传reserved→uploaded→pending_scan→ready／rejected，预占在失败释放，上传验证前不排版。folder移动在事务内查租户／角色／循环／深度／同名与revision。批量失败不隐含部分成功；引用中的素材阻断删除并显示影响。

对象locator不可从当前basePrefix反推。迁移copy→hash_verified→locator_switched→retained→cleaned；活动snapshot pin的旧位置保留，不能变成只读新位置的可变别名。取消迁移不会自动删除已经被新作品使用的副本。

逻辑trash立即限制新使用，但既有合法引用／活动任务按pin合同处理；物理purge必须再次查pin、保留期限和删除标记。账号注销立即撤销会话、分享和新任务入口；财务／审计按核验规则保留，用户原片依公开周期删除。备份恢复重放tombstone，防止删除数据复活。

## 6. 状态边界测试

每条状态边同时测试正常、重放、乱序、并发和崩溃恢复；不存在的边返回冲突，不允许管理员任意改成功状态代替正常账本／审核。数据库实际SQL保证项及服务事务保证项见database/transaction-safety.md，测试目录的cases.csv提供对应ID。
