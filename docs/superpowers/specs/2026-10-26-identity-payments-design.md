# 邮箱、微信身份与真实支付

用户已确定 Web 使用邮箱，小程序使用微信，支付使用微信及支付宝；本地 Codex 负责部署。2026-10-26 用户回复“开发”，授权直接实施前述主动绑定方案。

## 目标与约束
沿用 TypeScript、PostgreSQL、现有会话、订单快照、权益、退款和审计内核。邮箱使用六位验证码（有效期 5 分钟、最多 5 次尝试、发送间隔 60 秒），密码不参与登录。邮件通过 SMTP 发送，不把验证码或密钥写日志。邮箱地址加密保存，身份索引保存摘要。验证码绑定用途、挑战和会话，单次使用；发送有邮箱及来源限流。微信使用官方 jscode2session，仅服务端持有 AppSecret，不接收客户端声称的 openid。

账号主动绑定，双方需重新验证。另一账号已有身份返回冲突，不自动迁移订单、资产或会员。保留现有会话、CSRF、权限检查。

Web 微信使用 Native 扫码，支付宝使用当面付预创建扫码。真实商户适配器负责签名、回调验签、原始响应验签、查单、关单及原路退款；金额使用整数分。微信 API v3 回调先验签再解密，支付宝 RSA2 对原始响应片段验签。未配置渠道不开放；不通过前端成功页发权益。小程序现有虚拟支付政策保留，普通商户号不等于虚拟支付权限。

## 方案
1. 扩展现有身份及订单系统（采用）：统一权益归属，保留审计与幂等，但需升级合同和数据库。
2. 外挂独立登录/收银系统：短期接入容易，但账号、订单和权益同步增加故障点，不采用。

## 交付
接口合同及生成类型、增量 SQL、邮件/微信/支付适配器、运行时配置、登录和绑定 UI、双支付入口、测试及服务器升级文档。真实邮件与商户联调取决于用户服务器配置，不冒充联调完成。商户凭据只由本地部署人员写入服务器。
